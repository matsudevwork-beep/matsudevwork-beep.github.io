# ブラウザの中で動く「字を読むAI」の調査（2026-11-07）

> 代表の依頼：「①（ブラウザの中でAIを動かす方法）を調べておいて」
> 決めるのは代表です。ここは調べた結果とおすすめです。

## 結論
**できます。おすすめは「自分たちで小さなAIを作る」方法です。**
学習に使う字は、すでにアプリに入っている KanjiVG の書き順データと、商用で使えるフォントから作ります（ゆらぎを加えて、手で書いたような字をたくさん作る）。
これなら、使ってよいか不明なデータを使わずにすみます。できたAIは数百KBほどで、スマホのブラウザでもすぐ動き、字は外に送りません。
同じAIを、あとでアプリ版にもそのまま入れられます。

## 3つの道のくらべ
| 方法 | 調べた結果 | 判定 |
|---|---|---|
| A. ブラウザに最初から入っている手書き認識（Handwriting Recognition API） | Chrome 99 から使えるが、公式の説明では ChromeOS の実装は**英語だけ**。iPhone の Safari では使えない | ✕ 使えない |
| B. 公開されている手書き文字データ（ETL文字データベース、産総研）で学習 | ひらがな・カタカナを含む約120万字。古い利用条件は「**営利目的でない場合だけ無料、商用は相談**」。2025-03-28 に条件が改定されたという情報もあるが、公式ページが一時的に開けず本文を確認できなかった。**再配布は禁止** | △ 使うなら産総研に確認が必要 |
| C. 自分たちで学習データを作る（KanjiVG の線＋フォント＋ゆらぎ） | KanjiVG は CC BY-SA 3.0（すでに使用中・料金なし）。フォントは OFL など商用OKのものを使う | ◎ おすすめ |

### 参考：公開されているもの
- ブラウザで動く手書き認識の例は、英字・数字のもの（TensorFlow.js）はあるが、**ひらがなでそのまま使えるものは見つからなかった**。
- ひらがな・カタカナを読む作例（Flutter アプリ）では、ひらがなとカタカナを1つのAIでまとめると取りちがえが増えたため、別々に分けていた。→ こちらも **ひらがな用・カタカナ用・すうじ用に分ける** のがよい。

## C のくわしい中身（案）
1. **学習用の字をつくる**（スクリプト）
   - KanjiVG の線を、少し回す・ゆがめる・線の太さや長さを変える・ふるえを加える、などして 1字あたり数千枚つくる
   - 商用OKのフォント（例：いま画面で使っている M PLUS Rounded 1c は OFL）でも字を描いてまぜる
2. **小さなAIを学習させる**（Mac で数分〜数十分）
   - 64×64 の白黒画像 → 「どの字か」と「どれくらい自信があるか」を出す、小さな画像認識（CNN）
3. **ブラウザに入れる**
   - TensorFlow.js か ONNX Runtime Web（どちらも無料）。AI本体は数百KB、読みこみ1回、判定は一瞬
4. **アプリでの使い方**
   - 書き終わった字を画像にして、AIが「読める字か」を判定 → せんせいの「はなまる」の材料にする
   - 本当の価値は、**「おてほん なしで かく」モード**が作れること。いまは道をなぞるので、ほぼ必ず読める字になるが、お手本なしで書いた字が「あ」と読めるかどうかは、AIでないと判定できない

## 気をつけること
- **ライセンスの表示**：KanjiVG から作った学習データやAIも、CC BY-SA 3.0 の条件（作者の表示・同じライセンス）にしたがう。いまの hiragana.js と同じあつかいでOK
- **子どもの字はかなりくずれる**：学習用の字は大人のお手本をゆがめたものなので、実際の子どもの字で試して、きびしすぎないか確かめる（「読めない」と言わない設計にする。自信が低いときは「もうすこし」ではなく、ほめる＋コツにとどめる）
- **「AI」と言ってよい範囲**：このAIは「字を読む」部分だけ。ほかの判定（まんなかを通れたか など）は、これまでどおりルールで行う。宣伝では「AIが字を読んで、はなまるを付けます」くらいにとどめる
- iPhone の Safari でも動くか、古いスマホで重くないかは、作ってから確かめる
